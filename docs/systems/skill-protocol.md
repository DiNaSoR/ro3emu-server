# Combat skill protocol and parameters

This part of the server consists of `CombatService.Protocol.cs` and `SkillParameterRules.cs`, tested by `SkillProtocolTests.cs`. It reads the same `SkillConfig` row for server casting and the client parameter notification. Each role keeps its temporary wheel rows, parameter signature, selection deltas, and training pause flag in `GameSession.SkillProtocol`. Boss cooldowns live on the actual `MonsterUnit` and are filtered to the requesting viewer's scene and AOI.

| Route | Implemented source and boundary |
| --- | --- |
| 31027 | A learned wheel slot changes to a configured mode row when a live buff's type-15 modifier selects that mode, and reverts on buff removal. The update uses `Replace` and the active manual plan's selected slot level (bounded by learned level), so a lower slotted rank is preserved. The durable wheel remains 5025. |
| 31132 | Active `BuffConfig._kSkillAttributeList` scope-0 entries for a learned group yield full effective scalar/list values. `isAll=true` replaces prior state; a group-0 empty record ensures the Lua `affectParamDict` check does not return before clearing a now-empty map. Buff changes, learned-plan changes, and scene load call `RefreshSkillParametersAsync`. |
| 31100/06/21/07 | `SendCastTimelineAsync` and `SendMonsterTimelineAsync` each select one route for one validated onset. High-priority/extra routing must come from a real cast/proc source; these are alternate packets, never duplicates of the same timeline. |
| 31120/08 | A cast whose template block holds exactly one bullet effect that the template never names sends one fixed-time bullet per target at the attack point and resolves the hit when it lands (Fire Bolt 12004 -> 1200411). `masterId` is the caster, `split` is `_kShowDmg[0]`, `fixedTime` the bullet's `m_fBulletLifeTime`, or for a speed bullet (`m_iBulletControlType` 1, Soul Strike 1200803) the 2D distance / `m_fBulletSpeed` as `LC_Bullet_Helper` flies it. See "Server-launched bullets" below. |
| 31119/09 | A bounded send method accepts resolved effect records with a valid skill/source. No source-backed independent producer is wired, so this route is **not qualified**. |
| 31122 | A per-viewer `SetSkillTargetSelectionAsync` emits only a changed tag for a visible target. No source-backed eligibility transition is wired, so this route is **not qualified**. |
| 31125/26/27 | Actual cooldown end times are stored on a live monster. The client requests 31127 for an NPC with `_iImportantSkill=1`; the server returns visible, unexpired entries or a target refusal. Scene transition clears client display via 31126. |
| 31129/33 | Actual resolved damage entries are sent without invented `FormulaInfo`. Numeric 1 pauses this viewer's statistics, numeric 2 resumes. Invalid op values get `ErrorCodes.Parameter`. |
| 31118 | Legacy scalar-only carrier. The inspected client routes 31132 to `LC_DynamicParamMgr.ProcessDynamicSkillParam`; emitting both would give two representations of one change. The server emits no 31118. |

`SkillParameterRules.Active` parses `[scope, selector, type, operation, value, optional index]`. Scope 0 is exact skill group. Arithmetic operation 1=add, 2=set, 5=basis-point multiply is **(inferred)** from exported buff tuples. Damage-vector index -1 applying to every component is **(inferred)** from rows such as BuffConfig 1246101 on SkillConfig 1220101 `[6000,8000]`; the focused test covers both components. The handled field types are cooldown 0, action time 21, chant 23/24, distance 25/26, target cap 27, damage arrays 29/30, SP/HP cost 35, mode 15 and queue eligibility 44. Type 35 tuples carry a seventh entry: `[scope, selector, 35, op, value, costIndex, position]` edits number `position` of `_kCost` tuple `costIndex` (-1 every tuple); every exported tuple names position 3, the flat amount of `[1, attr, ratio, flat]` **(inferred)**. 31132 sends type 35 as `affectValueListList`, the whole effective cost list, which the client checks instead of the configured `_kCost` (`LC_DynamicParamMgr.GetDynamicSkillCost`, `LC_Skill_Function.CheckSkillCost`). The other structured tuple types 33/34/36-38 need recovered source semantics before they can alter combat; they are intentionally not applied.

**SP consumption.** AttributeConfig 1232 `per_sp_dedution` (SP consumption %, basis points, floor -9900) comes from cards (-20%, +10%, +15%) and buffs (Mana Recharge -1..-10%, 23392 +10..+20%). No client code reads it, so `CombatService.SpCost` multiplies every SP cost by `(10000 + value) / 10000`, rounded down **(inferred, classic RO)**, and 31132 sends the reduced cost list for every learned SP skill while the value is nonzero (refreshed on buff, skill, scene and equipment changes). Mana Recharge's own type-35 tuple uses selector -1 under scope 0 and is not parsed, so the -10% is not taken twice. Direct `_kAttri` on the highest learned mode-0 passive row contributes attributes once. `SpecialEffectConfig` opcode 16 weapon conditions are not decoded by the exported `enum_SpecialEffectType`, so they remain outside this implementation.

**Tooltip SP cost.** The skill tooltip (`UI_Com_Skill_PopupItemWidgetCtrl`, the hotbar's `LC_TipHelper.PopSkillTipPCJoyStick`) builds a "Cost: SP*n" line (UIWords 33075/2073) from the configured `_kCost` (`Lua_CFG_SkillConfig.GetCostSP`), not from the 31132 cost list, and the prefab never shows that label (cast time and cooldown show). Nothing the server sends changes it, so ClientHooks `SkillTipCost` rebuilds the line with the amount from `Lua_CFG_SkillConfig.GetCosts` (the list the cast is checked against) and shows it in a copy of the cooldown label.

Mode rows are looked up by actual `(group, level, mode)` identities, never arithmetic ID guesses. A client-submitted nonzero mode row must match the active type-15 mode modifier. `LC_DynamicParamMgr.lua:196-214,366-386` consumes type 15 as the skill attack mode. A requested base row resolves to the configured mode row while it is active. The same resolved row feeds `_iCD`, chant, range, damage and cost validation in the cast owner. A mode without a configured row falls back to base. `Lua_CFG_SkillConfig.GetHighBuffInfo` at lines 2526-2674 parses `_kSkillHighParam` buff/group/energy terms into keys supplied by its final tuple member. Those conditions are not used as a cast eligibility gate: the export does not show such a use, and their effect-tier purpose remains **(inferred)**.

The client evidence is `re/clientB/lua-src/Logic/Asset/LC_DAL_Joystick.lua:48-95` for 31027, `Logic/Skill/LC_DynamicParamMgr.lua:20-320` and `Network/NW_GameServerHandler.lua:960-965,1728-1746` for 31132, `Logic/Scene/LC_Scene_Sync.lua:3730-3896,3898-4434,4521-4539,4742-4762,7766-7912` for route handling, `Logic/Asset/LC_DAL_BossShowSkill.lua:8-73` and `Logic/Selector/LC_SelectorManager.lua:2474-2494` for boss display, and `Logic/Damage/LC_DamageStatistics.lua:378-405,450-538` for training. ## A new cast during a live one

The client sends 31102 for every press, even mid-cast, so the server decides whether a live cast gives way. It follows `LC_Skill_RunTimeContext.SkillCanInterrupted` / `GetSkillCanInterrupted` on the live cast's row: `_iInterruptedType` 1 (normal attacks) yields to any other skill at once but not to its own group, unless its hit has already landed on a target that is now dead or gone (**inferred**: nothing is left to deal, so the next target need not wait out the animation tail); 2 yields once the template's `m_fInterruptTime` has passed (mapped onto the cast timeline like `m_kAtkPoints`, never before the chant ends; a template without one holds to the end); every other type holds until the cast ends. A press that does not break the live cast gets 3005 (`SkillBusy`) and the live cast keeps going. `_bCancelCast` plays no part: the client reads it only to show the cancel button while aiming (`LC_SkillInput_Handler_Default.CheckShowCancelBtn`). Treating it as "may recast" let a held or spammed Normal Attack restart its swing every press, landing a hit each time, and refused Smite during the auto-attack cycle.

## Server-launched bullets

The client only flies a skill bullet in two ways: from the template's own `m_kClientPoints` (`LC_Skill_RunTimeContext.PlayClientEffect`, 19 templates), or when the server sends 31120/31108 (`LC_Scene_Sync._skillFixTimeBullet` -> `LC_PerformEffect_Agent.SkillCreateFixTimeBullet`, which drops the packet unless `masterId` names a visible unit and the effect's `m_kDamage.m_kDamageType` is 2, Bullet). 234 templates have a bullet effect in their `scriptShow*100..+99` block that neither `m_kShows` nor `m_kClientPoints` names, among them the Mage bolts: Fire Bolt 1200411, Lightning Bolt 1200503, Cold Bolt 1200603, Soul Strike 1200803 (Fire Ball 12012 has two candidates and gets none). Without 31120 a Fire Bolt plays its chant, lock-on and cast animation from the timeline and the hit spark from 31101, but no bolt flies.

`CombatService.ServerBullet` picks the block's single unreferenced bullet (several or none: no bullet) **(inferred)**: no config table maps a skill to its bullet, so the official server script owns that choice. `LC_BulletEmit_Mgr` emits `split` bullets `m_fBulletHatchInterval` apart, and `LC_DamageHelper.ProcessDamageWord` cuts 31101's total into `split` numbers when the hit effect has `m_isPlayShow_Multistage` (1200404: 0.1 s apart), so both packets carry `split = _kShowDmg[0]` (Fire Bolt level N: N). The bullet is sent at the template attack point; damage, 31101 and the damage numbers follow when the first bolt lands, `m_fBulletLifeTime` (Fire Bolt 400 ms) later **(inferred)**, scheduled one 50 ms loop tick early because loop timers fire on the next tick (in game, a full-flight timer left the first bolt fading before its hit showed): the remaining `split - 1` bolts arrive `m_fBulletHatchInterval` apart, which is also 1200404's `m_fDisplayInterval`. A skill whose hit effect does not spread the numbers (no `m_isPlayShow_Multistage` or a zero `m_fDisplayInterval`: Jupitel Thunder's 1210203, 10 bolts 250 ms apart) would show every number with the first bolt, so it lands each bolt as its own 31101 at its bolt's time with `split` 1 and its share of the damage; its buffs, procs and pushes come with the first bolt **(inferred)** (`SkillCombatTests.JupitelThunderLandsEachBoltAsItsOwnHit`). A launched cast (`ActiveSkillCast.Launched`) still lands if the caster moves or casts again; caster death, a scene change or a new attachment drop it, and its interrupt 31103 no longer sets `clearEffect`. `MapTests.FireBoltLaunchesItsServerBoltsAndShowsOneHitPerLevel` covers the packets, the landing delay and a walk during the flight.

## When cast costs are spent

`CastCoreAsync` checks every `_kCost` term when 31102 is accepted. A skill with no chant (`_iChantFix + _iChantVar == 0`) pays HP/SP and buff-pile costs at once. A chanted skill pays them when its chant completes, or at its impact if that comes first, so moving or interrupting during the chant costs nothing. If the caster no longer has the cost at that moment, the cast ends with 31104 Interrupted carrying the cost error and nothing is spent. This follows classic Ragnarok Online (rAthena consumes SP in `skill_castend`); the RO3 client only pre-checks costs (`LC_Skill_Function.CheckSkillCost`) and never shows when they are spent, so the timing is **(inferred)**. Item costs (the economy receipt) and energy are still spent on accept.

## Auto-attack after walking into range

Clicking an enemy out of range makes the client walk, send 31102 on reaching range and send its stop a few milliseconds later (in-game 11.10). `CombatService.PlayerMoved` ends the server's auto-attack loop when the player moves off its start point, so that stop used to end the loop after one swing: clicking from afar attacked once, clicking from close kept attacking. A loop or cast started while walking now takes the stop that follows within 300 ms as its real start, as long as it lands within the distance the walk could have covered. That distance uses the walk speed at the request, because the cast dismount (`MountService.DismountForCastAsync`) lowers the speed before the stop arrives. `SkillCombatTests.AnAutoAttackStartedOnTheWayInKeepsSwingingAfterTheArrivalStop` covers it.

## Casting while walking

The client sends a skill pressed mid-walk without stopping first: `LC_Skill_ActionPreCheck.CheckSkillSendServer` sends its position (`ForceSendPos`) and then 31102. It stops only when the server forbids walking: `LC_Unit_Player.IsSkillBlockMove` reads the `StatusForbidden` Walk bit (`enum_ForbiddenState.Walk` = 4), and the joystick and path controllers stop and hold the move input while it is set. A skill that lets the caster walk (`_bMovement` 1 UnLock, 2 WalkUnLock) plays on top of the walk instead. The server never sent that bit for a cast, so the client kept walking and its next step cancelled the cast as a move.

Now a player's cast of a Lock skill (`_bMovement` 0) sets `GameSession.CastMoveLockId`, which `BuffService` adds to the Walk forbid bit in 31048. The lock lifts at the cast's hit (past it the client lets a move break the skill: `LC_State_Unit_Skill` ReadyToEnd with `IsCanMoveBreak`), on a cancel, at the cast's end, or on a scene change. Walk requests stay accepted while it is set (`BuffService.HasForbidden` reads buff ordinals, not this bit), and the steps the client sent before it heard of the cast, plus its stop, move the cast's origin when they come within 300 ms and within the walk slack of where the cast started. A chant (`_iChantFix`/`_iChantVar`) of a Lock skill now roots the caster for its whole length, so its walk steps no longer cancel it. Move input cancels it through a 31124 request instead (next section), as does the cancel button (`_bCancelCast`). `SkillCombatTests.ACastPressedMidWalkLocksMovementAndSurvivesTheStepsInFlight` covers it.

A skill whose hit falls inside the first 50 ms loop tick (Grimtooth: template `m_kAtkPoints` [0]; about 880 skill groups) takes no lock: there is nothing to hold still for, and in game the lock going on and off within one tick around Grimtooth's dash left the player unable to walk until the next Grimtooth. The client's skill displacement (`LC_PerformEffect_Agent.SetBlockInputState`) drives the same `StopRayCastMove` and `LJ_BlockMove` flags as the Walk bit (`LC_Unit_Player.ChangeForbidden`), and they are plain booleans, so the last sender wins **(inferred cause)**. Such a skill cast mid-walk resolves at once and the walk carries on. If announcing a cast fails after it took the lock, the lock is lifted there, since nothing was scheduled to lift it. `SkillCombatTests.ASkillThatHitsAtOnceTakesNoMovementLock` covers it.

## Move input during a locked cast

While the Walk forbid bit is set, the client does not walk on a move key or a ground click. It sends a bare 31124 SkillInterruptReq (no `interruptSkillId`) instead: `LC_UnitChecker.CheckClearCacheSkill` does it when the player is in the Skill state, has a cached skill (every 31102 sets one) and `IsSkillBlockMove` is true. It is called from the keyboard joystick and from the ground-click move (`LC_Actor_ControlMove`). The client stays in the skill unless the reply says `is_interrupt_succ` (`LC_Scene_Sync._skillInterrupt` then calls `SkillInterruptServer`). The server used to grant every one, so a click right after placing a ground spell, or a move key during its chant, cancelled it after its cooldown had started: the spell showed nothing and stayed on cooldown.

Now `CombatService.MoveBreaksCast` grants a bare request (move cancels the cast, Steven's call) except in the cast's first 300 ms (`MoveCancelGraceMs`), where the placing click lands **(inferred window)**. Normal attacks (`_iInterruptedType` 1) and casts past their hit break at once. Requests that name a skill (the cancel button, a press with `nxtSkill`) cancel at once.

A cast cancelled before its hit (move, cancel button, a newer cast, a chant whose cost is gone) also gives back the cooldowns it started on accept, with a 31113 SkillCdNotify ending them now (`notPlayCdRefreshEffect` set). A cooldown something else raised since stays. Items and energy stay spent, as before. `SkillCombatTests.ThePlacingClickRightAfterAGroundCastDoesNotDropTheSpell`, `MovingDuringAGroundChantCancelsItWithoutCooldown` and `ACastCancelledBeforeItsHitRefundsItsCooldown` cover it.

## Buff visuals on support casts

A skill template's `m_kShows` only plays the caster's cast animation and sound (Blessing 14001: 1400103 `CastingSpell`, 1400199 audio). The buff's own gfx lives in the template's hit effect, the one `ShowPoint` names (Blessing 1400102 `fx_buff_angelblessing`, Increase AGI 1401004 `fx_buff_increaseagi`), and the client plays it only for a dst of 31101 (`LC_DamageHelper._ActionJumpDamage` -> `ShowHitDisplay`). A support cast with no damage or heal sent no 31101, so Blessing, Increase AGI, Angelus and the cleanses played their cast pose and nothing on the recipients.

`ApplyEffectsAsync` now adds each recipient of a friendly, non-damaging, non-field cast to that cast's 31101 as a display-only entry: damage 0, `DamageType_DamageShare`, `HitResult` Normal. The client's damage-word lookup maps that pair to `enum_HudWordType.None`, so no number is drawn **(inferred: the official server's choice of carrier is unknown)**. The entries skip damage statistics, energy and charge conversion, and the 31101 also goes to recipients outside the caster's view. `SkillCombatTests.BlessingShowsItsBuffEffectOnEveryRecipient` covers it.
