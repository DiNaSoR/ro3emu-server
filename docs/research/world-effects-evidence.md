# World effects: transport, ownership and limits

The implementation is a bounded server-owned presentation layer. It does not claim original encounter-script parity. An exact-name source search covered all 517 `data/config/*.json`, 381 `data/sceneeditor/*` (including `*_monsteridmap.json`), 172 `data/nav/*`, 2 `data/loc/*`, 13,488 files in each of the two decompiled Lua trees in your local `re/` folder (`re/lua-src` and `re/clientB/lua-src`, Config and Logic included), 2,277 `re/decomp/*` files and 147 proto files. Patterns include all scoped protocol names, message class names, `Mover`, `ForceField`, `Enforce` and `BossShout`. Focused follow-up searches parsed the complete exported `NPCConfig`, `SkillConfig`, `UnitConfig`, `MapConfig`, `DungeonConfig` and `ChatConfig` tables for effect-related keys. This is a source inventory, not an original-server runtime capture.

Exact protocol-name searches returned no hits in `data/config`, `data/sceneeditor`, `data/nav`, `data/loc` or `re/decomp`, and only network/consumer definitions in the two full Lua trees. `data/config/SkillConfig.json` `_kShout` is a skill-call boolean and delay (`Lua_CFG_SkillConfig.lua:2007-2028`), not a 31028 localization ID; all 52xxxxx boss skill rows have no nonzero `_kShout` value. `NPCConfig._iMoveByForce` is zero for all monster rows and does not specify a force field. `UnitConfig._kAnimations` is a static unit asset string, not a 31026 animation override map. The scene-editor and map Lua searches for `forceField`, `customField`, mover packet flags, `shoutId` and `cliFuncname` found no authored producer. These findings justify withholding historical triggers; they do not prove an original server never sent the packets.

The service keeps effect state by actual world-scene key and live monster reference. New AOI viewers get the unit base before per-unit effect replay through `World.UnitEntered`; scene-level state is replayed from `SceneService.AfterLoaded` after `World.JoinAsync`. Field timers carry the exact stored object so a stale timer cannot remove a replacement field. No effect command is accepted from a normal game message; operator commands use the existing GM account gate. The `!forcefield` command changes client movement but server force physics and its interaction with enforced walk validation need original-server evidence before gameplay qualification.

Validation: `tests/Ro3Emu.Tests/WorldEffectsTests.cs` covers force-field/latency replay and expiry, local-only face, and boss shout/turn validation. This is transport/state evidence; historical encounter producers and server force physics described above remain unqualified. See also [world-core-evidence.md](world-core-evidence.md).
