# MG_Common and developer wire evidence

The request/response names and fields are from `data/msgtable.tsv`, `MG_Common.proto:814-833,1320-1341`, `MG_Login.proto:121-146`, and `MG_Scene.proto:628-675`. An exact-token search covered all `data/config/*.json`, `data/sceneeditor/*` including monster ID maps, `data/nav`, `data/loc`, both decompiled Lua trees under your local `re/` folder (Config and Logic included), the decompiled C# and the protos. The relevant patterns are `GMCOMMAND_TRANSMIT`, `GMCommandTransmitReq`, `INSPECT_COMMAND`, `InspectCommandReq`, `PROC_GM`, `GMProcReq`, `DEBUG_SHOW_HEIGHT_NTF`, and `DebugShowHeightNtf`. An additional recursive exact-token search for `OnlineClientHeartReq`, `OnlineClientHeartResp`, and `ONLINE_STATU_HEART` covered the same scopes: no hits in config (517 files), sceneeditor (381), nav (172), loc (2), or decomp (2,277); both Lua trees (13,488 files each) contain only `Network/NW_Helper_PBDefine.lua:110-113` and `PBTypeDefine/PBEnumDefine.lua:2063`; the protos (147) contain `MG_Define.proto:20` and the response `MG_Login.proto:121`. Thus no `OnlineClientHeartReq` protobuf definition is recovered, and no Lua sender was located by these exact tokens. These are bounded exact-name observations, not proof that the native client never sends a message.
